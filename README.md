# R큐브 (R-Cube) 로봇 시스템

준산업용 로봇모듈 **R큐브**의 소프트웨어 저장소입니다. 각 R큐브는 QDD 모터를 내장한 10cm 정육면체 모듈로, BLE/CAN으로 연결해 로봇을 구성합니다.

## 저장소 구조

| 디렉토리 | 내용 | 담당 |
|---|---|---|
| `esp32/` | R큐브 메인보드 펌웨어 (ESP32-S3, ESP-IDF/FreeRTOS SMP). 단일 바이너리가 부팅 분기로 멤버/edge central/BLE 허브/설정모드 역할 수행 | 내부 개발 |
| `app/` | PC 제어 프로그램 (BLE·USB-CAN 제어, 통신방식 세팅, 미션 업로드) | 내부 개발 |
| `shared-protocol/` | R큐브 BLE/CAN 응용계층 정의 — OpCode·ResultCode·패킷 구조체. **esp32와 app의 단일 소스** | 내부 개발 |
| `vendor/motor-board/` | 모터제어보드(STM32G4) **UART 프로토콜 스펙** — 외부 업체 개발, 읽기 전용 계약 | 외부 업체 |
| `tools/` | 개발 보조 도구 (모터보드 UART 시뮬레이터 등) | 내부 개발 |
| `docs/` | 기획서·프로토콜·개발 로드맵 | 내부 개발 |

> 모터제어보드(STM32G4) 펌웨어는 **외부 업체가 개발**합니다. 본 저장소는 그 UART 프로토콜을 통해 위치/속도를 제어하고 상태를 수신하는 ESP32 쪽 어댑터만 구현합니다.

## 아키텍처 요약

- **제어 분담:** ESP32(20~50Hz 키프레임 생성·감독) → UART → STM32G4(1kHz+ 실시간 서보·보간).
- **듀얼코어:** Core 1 = 실시간 모션(고정주기), Core 0 = 통신(NimBLE/TWAI)·역할 레이어·MicroPython.
- **전송계층 무관:** 응용계층(OpCode·필드·ACK)은 BLE/CAN 공유. 통신은 얇은 어댑터로 분리.
- **역할은 부팅 분기:** 플래시의 ECF/CMF/멤버맵을 읽어 스택·역할 결정(단일 펌웨어).

## 개발 순서

`docs/R큐브_개발_로드맵.md` 참조. 임계경로: **프로토콜 헤더 고정 → 단일 큐브 관통(BLE 먼저) → 멀티큐브 → 독립로봇유닛 → 모션 고도화 → 안전/OTA**.

## 빌드 (준비 중)

- ESP32: ESP-IDF v5.x (`idf.py build flash monitor`)
- PC 앱: Python 3.x (`app/` 참조)
